# Governance

## 1. Stewardship

The Nally Project follows a steward model. The organisation is the initial project steward and maintains the project's purpose, repositories, standards, and governance records.

Stewardship is a responsibility to the project and its community—not an unlimited authority over users' personal data, devices, or deployments.

## 2. Principles

- Decisions and their rationale should be documented.
- Technical direction should be evidence-led.
- Contributions should be evaluated on merit and project alignment.
- Security and user autonomy take priority over convenience.
- Governance should evolve as the contributor community grows.

## 3. Decision levels

**Project-wide decisions:** Mission, governance, licensing strategy, compatibility commitments, and foundational architecture. These require a public proposal and steward decision.

**Technical decisions:** Component design, APIs, implementation patterns, and testing. These should be discussed in the relevant repository and recorded in an accepted design note or pull request.

**Maintenance decisions:** Documentation corrections, dependency updates, and low-risk fixes may follow normal maintainer review.

## 4. Proposals

A significant proposal should include:
1. Problem and intended outcome.
2. Evidence and alternatives considered.
3. Security, privacy, and accessibility implications.
4. Compatibility and migration impact.
5. Operational and maintenance costs.
6. Testing and success measures.

## 5. Conflicts of interest

Maintainers should disclose relevant conflicts when they could reasonably affect a decision. Decisions should be based on documented project interests.

## 6. Community growth

As the project gains sustained contributors, stewardship responsibilities, review authority, and succession procedures should be expanded transparently. Changes to this document should be proposed publicly and recorded in version history.
