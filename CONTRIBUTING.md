# Contributing

Thank you for considering a contribution to The Nally Project.

## Before contributing

- Read the project charter and architecture principles.
- Check existing issues and discussions before starting substantial work.
- For large changes, open a proposal first so design and scope can be agreed before implementation.

## Contribution process

1. Describe the problem you are solving.
2. Explain the proposed change and relevant alternatives.
3. Identify security, privacy, accessibility, and compatibility implications.
4. Add or update tests and documentation.
5. Submit a focused pull request with a clear description.

## Engineering expectations

- Prefer small, reviewable changes.
- Keep interfaces documented and avoid unnecessary coupling.
- Do not commit credentials, private keys, personal data, or production secrets.
- Validate and constrain external input.
- Use least-privilege permissions.
- Include tests for important behaviour and failure cases.
- Explain new dependencies and their licences.

## AI-assisted contributions

AI tools may be used, but contributors remain responsible for correctness, licensing, security, tests, and the final submission. Do not submit generated code or documentation that you have not reviewed.

## Reporting issues

Use GitHub Issues for ordinary bugs and feature proposals. Do not disclose exploitable vulnerabilities in public issues; follow SECURITY.md instead.

By participating, contributors agree to follow the Code of Conduct.
